# Требования: Система управления проектами, задачами и правками (Traking)

## 1. Общее описание

Traking — веб-приложение (PWA) для управления проектами, задачами, правками и коммуникацией между руководителями и исполнителями. Главная ценность — контроль правок в виде дерева задач, где видно: что нужно сделать, кто ответственный, что уже исправлено, что ещё открыто и почему задача не закрыта.

## 2. Формат приложения

- **Веб-приложение** — работает в браузере (десктоп, планшет, телефон)
- **PWA** — установка на главный экран, manifest.json, service-worker.js, адаптивная вёрстка, HTTPS
- Push-уведомления — отложены на второй этап

## 3. Роли пользователей

### 3.1. Admin
- Полный доступ ко всем данным и функциям
- Управление пользователями, ролями, справочниками статусов
- Просмотр журнала действий

### 3.2. Руководитель (Manager)
- Создание и редактирование проектов
- Управление задачами, подзадачами, сроками, статусами
- Назначение исполнителей
- Просмотр всех задач и комментариев своих проектов
- Загрузка документов, файлов, ссылок

### 3.3. Исполнитель (Executor)
- Видит только проекты и задачи, к которым подключён
- Пишет комментарии, загружает материалы
- Меняет статус своих задач
- Не видит чужие задачи и переписки
- Может переназначать задачу (настраиваемо)

## 4. Основные модули

### 4.1. Авторизация
- Вход по логину и паролю
- Токен в HttpOnly/Secure/SameSite cookie на 3 месяца
- Хэш токена хранится в БД
- Пароли — password_hash() / password_verify()
- Выход, восстановление доступа (второй этап)

### 4.2. Управление пользователями (Admin)
- CRUD пользователей
- Назначение ролей, активация/деактивация
- Сброс пароля, фильтры, поиск

### 4.3. Проекты
- Название, описание, срок сдачи, статус
- Руководители и исполнители (many-to-many)
- Документы проекта (файлы, ссылки, заметки)
- Типы документов: КП, бриф, ТЗ, договор, смета, презентация, ссылка Figma, ссылка на облако, другое

### 4.4. Задачи и дерево правок
- Задача принадлежит проекту
- Поле parent_id — бесконечная вложенность подзадач
- Поля: название, описание, статус, приоритет, срок, автор, исполнитель, даты
- **Ограничение:** задача не может быть закрыта при открытых подзадачах

### 4.5. Комментарии и чаты
- Чат проекта (общий)
- Чат задачи
- Чат подзадачи (отдельный поток)
- Видимость: руководитель видит всё; исполнитель — только свои задачи

### 4.6. Файлы и вложения
- Загрузка: изображения, PDF, DOC/DOCX, XLS/XLSX, архивы, видео
- Ограничения: размер, тип, количество
- Хранение: /uploads/projects/{project_id}/tasks/{task_id}/filename.ext

### 4.7. Уведомления (внутренние)
- Счётчик в шапке
- Прочитанные / непрочитанные
- Переход в задачу по клику
- События: назначение задачи, комментарий, смена статуса, смена срока, переназначение, упоминание

### 4.8. История действий (Activity Log)
- Фиксация всех ключевых событий
- Анализ: кто что сделал, когда, сколько правок

### 4.9. Аналитика (базовая)
- Для руководителя: всего задач, открыто, на проверке, просрочено, среднее время закрытия
- Для администратора: активность, нагрузка, просроченные
- Для исполнителя: мои задачи по статусам

## 5. Статусы

### 5.1. Статусы проекта
- Новый → В работе → На паузе → На проверке → Завершён → Отменён

### 5.2. Статусы задачи
- Сделать → В работе → Проверка → Правки → Закрыто → Отменено
- Подзадачи: Открыто → В работе → Проверка → Закрыто

### 5.3. Жизненный цикл
- Основной: Сделать → В работе → Проверка → Закрыто
- С правками: Проверка → Правки → В работе → Проверка → Закрыто

## 6. Права доступа

| Действие | Admin | Руководитель | Исполнитель |
|----------|-------|-------------|-------------|
| Видеть все проекты | ✓ | Только свои | Только свои |
| Создавать проект | ✓ | ✓ | ✗ |
| Создавать задачи | ✓ | В своих проектах | ✗ |
| Назначать исполнителей | ✓ | ✓ | ✗ |
| Менять статус задачи | ✓ | ✓ | Только своих |
| Закрывать задачи | ✓ | ✓ | ✗ |
| Видеть все комментарии | ✓ | В своих проектах | Только в своих задачах |
| Переназначать задачу | ✓ | ✓ | Настраиваемо |
| Управлять пользователями | ✓ | ✗ | ✗ |

## 7. Экраны приложения

1. **Вход** — логин, пароль, кнопка «Войти»
2. **Дашборд** — зависит от роли
3. **Список проектов** — карточки с фильтрами
4. **Карточка проекта** — инфо, документы, участники, задачи, чат, история
5. **Список задач** — вид списком и деревом (канбан — второй этап)
6. **Карточка задачи** — главный рабочий экран (описание, статус, комментарии, файлы, подзадачи, история)
7. **Уведомления** — список с фильтрами
8. **Пользователи** (admin) — CRUD

## 8. Технический стек

- **Backend:** Чистый PHP 8.x (без фреймворка), MySQL, свой микро-каркас (MVC)
- **Frontend:** Tailwind CSS (CDN) + Alpine.js (CDN), vanilla JS для AJAX
- **Архитектура:** гибрид (PHP рендерит страницы, AJAX обновляет комментарии/статусы/уведомления)
- **PWA:** manifest.json, service-worker.js вручную, иконки, HTTPS
- **Хостинг:** Shared-хостинг Hostiman (ispmanager), SSH + FTP
- **Не требуется:** Node.js, Composer на сервере, очереди, Redis

## 9. Структура базы данных

### Таблицы:
- `users` — id, name, email, login, password_hash, role_id, status, created_at, updated_at, last_login_at
- `roles` — id, code, name
- `auth_tokens` — id, user_id, token_hash, expires_at, created_at, last_used_at, user_agent, ip_address
- `projects` — id, title, description, deadline, status_id, created_by, created_at, updated_at, closed_at
- `project_users` — id, project_id, user_id, project_role, created_at
- `project_documents` — id, project_id, title, document_type, file_path, external_url, comment, uploaded_by, created_at
- `project_statuses` — id, code, name, sort_order
- `tasks` — id, project_id, parent_id, title, description, status_id, priority, deadline, created_by, assigned_to, created_at, updated_at, closed_at
- `task_statuses` — id, code, name, sort_order
- `task_participants` — id, task_id, user_id, role, created_at
- `task_comments` — id, task_id, user_id, comment_text, created_at, updated_at, parent_comment_id
- `task_files` — id, task_id, comment_id, uploaded_by, file_name, file_path, file_type, file_size, created_at
- `task_links` — id, task_id, comment_id, user_id, url, title, created_at
- `notifications` — id, user_id, type, title, message, project_id, task_id, comment_id, is_read, created_at, read_at
- `activity_log` — id, user_id, project_id, task_id, action_type, old_value, new_value, created_at

## 10. Переназначение задач

- Руководитель: назначает любому исполнителю проекта
- Исполнитель: настраиваемо (самостоятельно / через подтверждение руководителя)
- MVP: исполнитель может переназначить только на другого исполнителя проекта

## 11. Поиск и фильтры

- Проекты: статус, руководитель, исполнитель, срок, дата создания
- Задачи: статус, исполнитель, автор, срок, приоритет, проект, новые комментарии, файлы, просрочено
- Комментарии: по тексту, автору, дате

## 12. MVP — минимальная версия

### Включено в MVP:
- Авторизация с запоминанием на 3 месяца
- Роли: admin, руководитель, исполнитель
- Управление пользователями (admin)
- Проекты: создание, участники, документы
- Задачи: создание, назначение, подзадачи, дерево
- Комментарии к задачам
- Загрузка файлов
- Смена статусов
- Уведомления внутри приложения
- История действий
- Адаптивная вёрстка
- PWA (иконка, установка на телефон)

### Отложено на следующий этап:
- Push-уведомления
- Канбан-доска
- Сложная аналитика
- Групповые чаты
- Экспорт отчётов

## 14. Ключевые архитектурные решения

1. Дерево задач через `parent_id`
2. Права видимости для исполнителей
3. История изменений (activity_log)
4. Безопасное хранение паролей (bcrypt)
5. Токены авторизации (не пароль в cookie)
6. Несколько руководителей и исполнителей в проекте
7. Несколько участников в задаче
8. Запрет закрытия задачи при открытых подзадачах
9. Мобильная адаптация
10. Структура: /app (Controllers, Models, Services, Middlewares, Views), /config, /public, /routes, /database, /storage
