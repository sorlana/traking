# Requirements Document

## Introduction

Функциональность учёта времени позволяет Исполнителю фиксировать затраченное время на выполнение задачи или доработки (подзадачи). Время вводится на вкладке «Информация» карточки задачи. Редактирование времени доступно до тех пор, пока задача (и все связанные доработки) не закрыта. Все изменения времени фиксируются в журнале действий (activity_log).

## Glossary

- **Система** — веб-приложение Traking для управления проектами и задачами
- **Исполнитель** — пользователь с ролью `executor` (role_id = 3), назначенный на задачу через поле `assigned_to`
- **Задача** — запись в таблице `tasks`, представляющая единицу работы в проекте
- **Доработка** — дочерняя задача (подзадача), связанная с родительской задачей через поле `parent_id`
- **Затраченное_время** — числовое значение в часах, отражающее время работы Исполнителя над задачей
- **Вкладка_Информация** — боковая панель (десктоп) или модальное окно «Детали» (мобильные) на странице карточки задачи
- **Журнал_действий** — таблица `activity_log`, хранящая историю всех действий пользователей
- **Закрытая_задача** — задача со статусом `closed` (status_code = 'closed')

## Requirements

### Requirement 1: Внесение затраченного времени

**User Story:** Как Исполнитель, я хочу внести время, потраченное на выполнение задачи, чтобы руководство могло отслеживать трудозатраты.

#### Acceptance Criteria

1. WHEN Исполнитель открывает Вкладку_Информация задачи, THE Система SHALL отображать поле ввода «Затраченное время» с текущим значением Затраченного_времени для данной задачи.
2. WHEN Исполнитель вводит значение Затраченного_времени и подтверждает сохранение, THE Система SHALL сохранить введённое значение в базе данных и связать его с текущей задачей.
3. THE Система SHALL принимать значение Затраченного_времени в формате десятичного числа с точностью до 0.5 часа (например: 0.5, 1, 1.5, 2, 8).
4. WHEN Исполнитель вводит значение Затраченного_времени, равное нулю или отрицательное число, THE Система SHALL отклонить ввод и отобразить сообщение об ошибке валидации.
5. WHEN Исполнитель вводит значение Затраченного_времени, превышающее 999.5 часов, THE Система SHALL отклонить ввод и отобразить сообщение об ошибке валидации.

### Requirement 2: Ограничение доступа к вводу времени

**User Story:** Как менеджер, я хочу, чтобы только назначенный Исполнитель мог вносить время по своей задаче, чтобы обеспечить достоверность данных о трудозатратах.

#### Acceptance Criteria

1. THE Система SHALL отображать поле ввода Затраченного_времени только пользователю, который назначен на задачу в качестве Исполнителя (значение `assigned_to` совпадает с `user_id` текущего пользователя).
2. WHEN пользователь, не являющийся назначенным Исполнителем данной задачи, пытается сохранить значение Затраченного_времени через API, THE Система SHALL отклонить запрос и вернуть ошибку 403 (Forbidden).
3. WHILE задача не имеет назначенного Исполнителя (поле `assigned_to` пустое), THE Система SHALL скрывать поле ввода Затраченного_времени на Вкладке_Информация.

### Requirement 3: Редактирование затраченного времени

**User Story:** Как Исполнитель, я хочу иметь возможность изменить ранее внесённое время, чтобы скорректировать данные при ошибке.

#### Acceptance Criteria

1. WHILE задача имеет статус, отличный от `closed`, THE Система SHALL разрешать Исполнителю редактировать значение Затраченного_времени.
2. WHEN задача переходит в статус `closed`, THE Система SHALL запретить редактирование Затраченного_времени и отображать поле только для чтения.
3. WHEN Исполнитель пытается сохранить Затраченное_время для Закрытой_задачи через API, THE Система SHALL отклонить запрос и вернуть ошибку 403 с сообщением «Задача закрыта, редактирование времени недоступно».
4. WHEN родительская задача закрыта, THE Система SHALL запретить редактирование Затраченного_времени во всех связанных Доработках (дочерних задачах).

### Requirement 4: Учёт времени в доработках

**User Story:** Как Исполнитель, я хочу вносить время отдельно для каждой доработки, чтобы детализировать трудозатраты по подзадачам.

#### Acceptance Criteria

1. WHEN Исполнитель открывает Вкладку_Информация Доработки, THE Система SHALL отображать поле ввода Затраченного_времени по тем же правилам, что и для основной задачи.
2. THE Система SHALL хранить значение Затраченного_времени отдельно для каждой задачи и каждой Доработки.
3. THE Система SHALL отображать суммарное Затраченное_время по родительской задаче и всем её Доработкам на Вкладке_Информация родительской задачи.

### Requirement 5: Логирование изменений времени в журнале действий

**User Story:** Как менеджер, я хочу видеть историю изменений затраченного времени, чтобы контролировать корректность данных.

#### Acceptance Criteria

1. WHEN Исполнитель впервые сохраняет значение Затраченного_времени, THE Система SHALL создать запись в Журнале_действий с action_type = 'time_logged', old_value = NULL, new_value = введённое значение.
2. WHEN Исполнитель изменяет значение Затраченного_времени, THE Система SHALL создать запись в Журнале_действий с action_type = 'time_updated', old_value = предыдущее значение, new_value = новое значение.
3. THE Система SHALL записывать в Журнал_действий user_id Исполнителя, project_id и task_id для каждого изменения Затраченного_времени.
4. THE Система SHALL отображать записи об изменении Затраченного_времени в истории действий на странице задачи.

### Requirement 6: Отображение затраченного времени

**User Story:** Как менеджер, я хочу видеть затраченное время на вкладке информации задачи, чтобы оценивать трудозатраты.

#### Acceptance Criteria

1. THE Система SHALL отображать текущее значение Затраченного_времени на Вкладке_Информация для всех пользователей, имеющих доступ к задаче.
2. WHEN значение Затраченного_времени не задано, THE Система SHALL отображать «—» (прочерк) вместо числового значения.
3. THE Система SHALL отображать Затраченное_время в формате «X ч» (например, «4.5 ч», «8 ч»).
